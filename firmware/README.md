# firmware/

Generated, and checked in on purpose.

`valence/` is the output of

```bash
ntx firmware valence --device nRF52840 --p-real 0.90 -o firmware/valence
```

It lives in the repo so CI can cross-compile and boot a real image without downloading
the 1.1 GB connectome release. Nothing here is written by hand — every file carries a
`generated by neuraltransistor` header, and editing one is a mistake that the next
regeneration silently reverts.

## What the boot check proves

`main.c` runs the circuit for 64 ticks against a fixed input and folds every spike into
an FNV-1a digest. The expected value in `cilicon.yml` was computed from the **numpy
reference** at emit time, so the console can only print it by computing the same spikes.
A green check means the int8 kernel is bit-exact on cross-compiled ARM — a stronger claim
than "it linked" or "it booted".

## Drift

CI builds these committed sources, so a change to the emitter that broke code generation
would not show up here on its own. What catches that is `ntx eval`, whose `cross_boot`
check regenerates the firmware from the live connectome on every run and boots *that*.
CI covers "the committed image is correct"; the eval suite covers "the emitter still
produces a correct image". Regenerate this directory whenever the emitter changes:

```bash
ntx firmware valence --device nRF52840 --p-real 0.90 -o firmware/valence
```

## Other circuits

Any circuit works — `ntx firmware compass`, `ntx firmware legs`, and so on. Only this one
is committed, because it is the smallest and the point is a CI image, not a library of
binaries. `docs/STATUS.md` carries the linker-measured sizes for all six.
